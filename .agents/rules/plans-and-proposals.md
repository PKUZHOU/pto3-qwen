# Plans and Proposals

## Core Principle

Plans should be concrete enough to review, implement, and validate without
guessing.

## Required Content

When presenting a plan or design proposal, include:

- the exact files or directories expected to change
- the implementation order when sequencing matters
- examples or sketches for non-obvious API or doc changes
- the validation strategy
- the open questions or trade-offs

## For Documentation-Focused PRs

Also include:

- which stable doc will eventually hold the final content
- which details stay temporary in `docs/in_progress/`
- what triggers the merge from in-progress docs into stable docs
