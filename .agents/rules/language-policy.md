# Language Policy

## Core Principle

Use English for intermediate work unless a repository document already has a
different established language that should be preserved.

## Use English For

- internal reasoning
- tool descriptions and status updates
- commit messages and PR text
- agent prompts and workflow notes
- new top-level rules, skills, and GitHub workflow docs

## Match Existing Document Language For

- edits to an existing doc that already has a clear language choice
- stable docs whose surrounding content would become inconsistent if one section
  changed language

## User-Facing Responses

Match the user's language in the final response unless there is a strong reason
to quote or preserve repository text as-is.
